# 全体要件定義書のリバースエンジニアリング作成

## 何を

`.kiro/specs/philosophy-dialog-app/requirements.md` を新規作成。既存の `backend/`・`frontend/` の実装コード（`accounts`/`matching`アプリのモデル・ビュー・シリアライザ・シグナル、フロントエンドのHome/Meeting画面）を読み、現状動作する仕様を要件定義書の形式（背景・Non-Goals・成功指標・ユーザーストーリー・EARS受け入れ基準）でリバースエンジニアリングして文書化した。あわせて、実装を読む過程で判明した不整合（マッチング成立とビデオ通話画面が未連携であること、`cancel_matching`が元の待機エントリを削除できていないことなど）を「既知の課題」として記録した。

## なぜ

ユーザーからの依頼。新規機能の設計に先立つ通常の要件定義とは異なり、既存実装の仕様を後から文書化して現状把握のベースラインとするため（`.kiro/specs/README.md`の通常フローとは別に、プロジェクト全体の現状仕様として作成）。
