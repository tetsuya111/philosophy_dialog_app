# ランダムコールの要件定義を新規作成

## 何を行ったか

- [.kiro/specs/random-call/requirements.md](../.kiro/specs/random-call/requirements.md) を新規作成した。
- 別プロジェクト（community_sns）の `.kiro/specs/random-call/requirements.md` の構成を参考に、待機列への参加・取りやめ・タイムアウト、4人マッチング、グループ専用通話ルームへの入室、通話終了と有効時間満了、フロントエンドからの認証済みAPI呼び出しをストーリーとして定義した。

## なぜ行ったか

- マッチング（`backend/matching/`）と通話画面（`frontend/app/meeting.tsx`）が連携しておらず、Home画面の「対話をはじめる」ボタンも機能していないため、本アプリの中核体験（4人ランダムマッチングでの哲学対話）が成立していない。

## 参考スペックからの主な変更点

- 対象クライアントを Web のみ → Android ネイティブ版・Web 版の両方に変更（既存の `Meeting.tsx` / `Meeting.web.tsx` を流用）。
- 通話画面は別スペックにせず、既存画面の流用として本スペック内で定義。
- 通話後のグループチャットは、本プロジェクトにDM基盤がないため Non-Goal とした。
- フロントエンドにログイン画面・API呼び出し処理がないこと、ログインAPIがCookieのみにトークンを返すが認証クラスはヘッダーを読むことを制約として明記し、ログイン画面の扱いを未解決事項とした。
